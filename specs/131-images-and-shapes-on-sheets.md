## Why
A workbook is not only cells. The logo in the corner of the invoice, the
screenshot pasted beside a defect log, the arrow pointing at the number that
matters, the text box explaining a model's assumptions — all of it lives in a
sheet's drawing layer, and today SPEC-116 carries it as bytes nobody shows:
the `xl/drawings/drawingN.xml` part sits in `opaque`, an `.ods` table's
`draw:frame` rides inside `Cell.preservedXml` (SPEC-122), and the grid paints
as if the sheet were bare. Worse, nothing follows the cells: insert ten rows
above a picture and the cells move while the picture stays where the file
put it, because nothing has ever read where that was.

The vocabulary already exists. `src/lib/core` holds the shape catalogue
(`shapeCatalogue.ts`, SPEC-069) with its painter (`shapeCanvas.ts`) and
gallery icons, the DrawingML preset maps and the `a:xfrm`/group helpers
(`drawingMl.ts`), the scheme-colour reader (`themeDrawingMl.ts`), the media
payload and its acceptance rules (`media.ts`, SPEC-024), natural-size probing
(`imageDimensions.ts`) and the MCE branch selector Word taught us we need
(`xml.ts` `selectAlternateContent`). What a sheet adds is the **anchor**: a
drawing is pinned to cells, not to a page, and the way it follows those cells
— move and size, move only, or neither — is a property of the drawing that
both formats store and every structural edit must honour.

**This file is the normative source for the cell-anchored drawing model
(`Sheet.drawings`, `SheetDrawing`, `DrawingAnchor`), how anchors follow row
and column edits, the xlsx `xdr:wsDr` and ODS `table:shapes`/in-cell drawing
wire mappings, the splice rule that keeps an untouched drawing byte-identical,
and the sheet drawing layer.** SPEC-132 widens its `chart` content kind;
SPEC-136 prints what this layer paints.

Fidelity outranks features exactly as SPEC-008 says. A sheet drawing's
content element is never regenerated by this spec: moving, resizing or
re-ordering a drawing patches its anchor and leaves the shape, picture or
foreign object inside it byte-for-byte as the producer wrote it. Only
drawings created here are written from the model.

## Out of scope
Editing a shape's fill, outline, text or geometry adjustments on a sheet
(rendered, preserved, never edited here — Backlog; the slide and page
surfaces own those editors), rotating a drawing by handle (rotation is
rendered), cropping, replacing or resetting a picture, duplicating or
copy/pasting drawings (SPEC-125's clipboard carries cells only — Backlog),
grouping and ungrouping, alignment guides and snapping to cells (Alt-drag
snap — Backlog), connectors that stay glued to shapes (an `xdr:cxnSp`
renders as its preset; its connection bindings are kept verbatim and not
followed), multi-select of drawings, form-control behaviour (a checkbox is a
face, never a control), OLE activation, SmartArt, text boxes as a separate
insert, sheet background pictures (`<picture>`), header/footer images and the
legacy VML drawing used by comments (SPEC-135) — all preserved. Charts
(SPEC-132 — this spec only places their frames). Printing drawings (SPEC-136).
Drawings in the library miniature. Performance of sheets with thousands of
drawings (SPEC-137).

### The drawing model
```ts
// src/lib/spreadsheet/model.ts (SPEC-131 additions)
export interface AnchorPoint { col: number; colOffEmu: number; row: number; rowOffEmu: number }
export interface DrawingAnchor {
  kind: "twoCell" | "oneCell" | "absolute";
  /** twoCell only — Excel's editAs. Absent = "twoCell" (the schema default). */
  editAs?: "twoCell" | "oneCell" | "absolute";
  from?: AnchorPoint;                    // twoCell, oneCell
  to?: AnchorPoint;                      // twoCell, as read or last written
  posEmu?: { x: number; y: number };     // absolute; twoCell+editAs "absolute" (derived at read)
  extEmu?: { cx: number; cy: number };   // oneCell, absolute; twoCell+editAs "oneCell"|"absolute" (derived at read)
}
export interface DrawingText {           // render-only subset of xdr:txBody / text:p
  paragraphs: { text: string; align?: "left" | "center" | "right" }[];
  anchor: "top" | "middle" | "bottom";
  sizePt?: number; color?: ModelColor; bold?: true;   // from the first run
}
export type SheetDrawingContent =
  | { kind: "image"; mediaId: string; crop?: { l: number; t: number; r: number; b: number } }  // fractions 0..1
  | { kind: "shape"; visual: ShapeVisual; text?: DrawingText }
  | { kind: "group"; members: { x: number; y: number; w: number; h: number;   // fractions of the group box
                                content: Exclude<SheetDrawingContent, { kind: "group" | "chart" }> }[] }
  | { kind: "chart"; sourcePart?: string }   // a placeholder here; SPEC-132 widens it
  | { kind: "foreign"; label: string; face?: Exclude<SheetDrawingContent, { kind: "group" | "chart" | "foreign" }> };
export interface SheetDrawing {
  id: string;              // minted at read ("dr1"…), never written; equalStructural ignores it
  anchor: DrawingAnchor;
  name: string;            // xdr:cNvPr@name / draw:name
  altText?: string;        // xdr:cNvPr@descr / svg:desc
  hidden?: true;           // xdr:cNvPr@hidden="1" — kept, never painted or selectable
  rotationDeg?: number;    // a:xfrm@rot / draw:transform rotate — rendered only
  /** The verbatim source element: xlsx the wsDr child (anchor, or the
   *  mc:AlternateContent around it); ods the draw:* element. Absent for a
   *  drawing created here. Never dropped by a move, resize or z-order change. */
  sourceXml?: string;
  content: SheetDrawingContent;
}
// Sheet gains: drawings?: SheetDrawing[]   (index 0 = back)
//              drawingPart?: string         ("xl/drawings/drawing1.xml")
//              drawingsDirty?: true         (xlsx: rebuild the drawing part only)
```
`ShapeVisual` is read as a subset: `geometry` (unknown presets keep
`unsupportedGeometryXml` and paint the dashed placeholder), `adjustments`,
`rotationDeg`, a solid or no fill (`a:solidFill` with `a:srgbClr` or a
scheme colour through `schemeClrRefFrom`; ODS `draw:fill`/`draw:fill-color`),
an outline (`a:ln@w`, its solid colour, `a:prstDash`; ODS `draw:stroke`,
`svg:stroke-color`, `svg:stroke-width`). A gradient, pattern or picture fill
paints as its first stop/foreground colour — the source stays verbatim, so
this approximation costs nothing on save. `a:style` references
(`fillRef`/`lnRef`, how Excel styles most shapes) resolve their scheme colour
the same way. `xdr:txBody`/`text:p` text reads into `DrawingText`.

### Anchors follow cells
`anchorBehaviour`: twoCell with `editAs` absent/`"twoCell"` → `moveAndSize`;
`oneCell`, or twoCell with `"oneCell"` → `move`; `absolute`, or twoCell with
`"absolute"` → `fixed`. At read, a twoCell anchor whose behaviour is `move`
gets `extEmu` (the from→to distance under the read-time geometry) and one
whose behaviour is `fixed` gets `posEmu` + `extEmu`; these are the drawing's
size truth from then on. A point's px position is `colLeft(col) +
min(colOffEmu / 9525, colWidth(col))` (rows likewise) — offsets are kept as
read, even when larger than their cell, and clamped only for rendering.

The `drawings` adjuster, for a `StructuralEdit` on the drawing's sheet (rows
shown; columns are symmetric):

| Edit | `moveAndSize` | `move` | `fixed` |
| --- | --- | --- | --- |
| insert `count` at `at ≤ from.row` | `from.row`, `to.row` += count | `from.row` += count | — |
| insert with `from.row < at ≤ to.row` | `to.row` += count (grows) | — | — |
| delete band containing neither point | points below shift up | `from` below shifts up | — |
| delete band containing `to` only | `to` = (`at`, 0) | — | — |
| delete band containing `from` only | `from` = (`at`, 0), `to` shifts up | `from` = (`at`, 0) | — |
| delete band containing both | drawing deleted (Excel's behaviour) | `from` = (`at`, 0) | — |

A `move` or `fixed` drawing is never deleted by a structural edit. Hiding
and resizing are not edits: the layer re-lays from the model, so
`moveAndSize` drawings stretch and collapse with their cells and the others
keep `extEmu`. **Recomputed points.** The writer derives a `move` anchor's
`to` (and a `fixed` twoCell anchor's `from`/`to`) from `extEmu`/`posEmu`
under the write-time geometry, and patches the source only when the derived
point differs from the source point by more than one pixel (9,525 EMU) on
either axis — Excel's own rounding never forces a rewrite.

Drawing parts are small; they are parsed with `parseXml` for content and
scanned with `scanXml` for each top-level child's exact source slice
(`sourceXml`, including the whitespace before it). `cNvPr` ids are read only
to mint new ones (`1 + max` in the part).

**MCE wrappers.** `UNDERSTOOD_SHEET_DRAWING_NAMESPACES` is an empty set in
this spec: no Office-2010+ drawing extension is something this product can
render better than its Fallback. Labels by the Choice's `Requires` namespace:
`a14` with a form-control `xdr:sp` (its `a14:compatExt`) → "Form control";
`sle15` → "Slicer"; `aink` → "Ink"; `cx1`/`cx2` (chartex) → "Chart"; `a14`
around a text body with `a14:m` → "Equation"; anything else → "Object". The
face is the Fallback's `xdr:pic` or catalogue `xdr:sp` when present and not
hidden, except for chartex, whose Fallback is Excel's "This chart isn't
available" text box and is never shown as a face. Adding a namespace to the
set later is how a future spec models a wrapped kind; SPEC-132 does not.

### Reading ODS drawings
- **Where.** `table:shapes` (a `table:table` child) → `absolute`, position
  `svg:x`/`svg:y`, size `svg:width`/`svg:height`. A `draw:*` element inside a
  `table:table-cell` → anchored to that cell (a repeated cell anchors at its
  first column). `svg:x`/`svg:y` of a cell-anchored shape are read as
  **sheet-absolute** (LibreOffice's importer re-derives the cell anchor from
  the absolute rectangle), so the start offset is `svg:x − colLeft(col)`
  clamped at 0; `table:end-cell-address` + `table:end-x`/`table:end-y` give
  `to` (a `twoCell` anchor); without them the anchor is `oneCell` with
  `extEmu` from `svg:width`/`svg:height`. A shape with `draw:transform` takes
  its translation (and `rotate`) from it.
- **What.** `draw:frame` > `draw:image` (`xlink:href` → `Pictures/…`,
  `fo:clip` in its graphic style → `crop`); `draw:custom-shape` with
  `draw:enhanced-geometry@draw:type` via `DRAW_TYPE_TO_GEOMETRY`
  (`non-primitive` or unknown → placeholder); `draw:rect`, `draw:ellipse`,
  `draw:line` → `rect`, `ellipse`, `line`; `draw:g` → `group`; `draw:frame` >
  `draw:object` → `chart` (`sourcePart` = `"Object N/content.xml"`); the rest
  `foreign` ("Object", "Form control" for `draw:control`, "3-D object").
  Fill and outline come from the automatic graphic style
  (`style:graphic-properties`). Alt text = `svg:desc`, name = `draw:name`.

### Writing
- **xlsx.** Clean sheet → drawing part and `.rels` verbatim. `drawingsDirty`
  → the part is rebuilt as described in the ACs; an imported anchor is
  patched with `scanXml` offsets (the `xdr:from`/`xdr:to` children rewritten
  as `<xdr:col>…<xdr:colOff>…<xdr:row>…<xdr:rowOff>…`, `xdr:pos`/`xdr:ext`
  attributes, `editAs` added/changed/removed, the content element's own
  transform — `a:xfrm` in `xdr:spPr`/`xdr:grpSpPr`, `xdr:xfrm` in a
  graphicFrame — given the anchor's absolute EMU box in `a:off`/`a:ext`
  unless all four were 0 in the source (Excel's graphicFrame convention), with
  `a:chOff`, `a:chExt`, `rot` and flips untouched). Inside an `mc:AlternateContent`
  every branch's anchor is patched identically.
- **ods.** The ODS table writer (SPEC-122) emits a dirty table's drawings
  from the model: `fixed` ones in a `table:shapes` element placed after
  `office:forms` and before the column definitions; `moveAndSize` and `move`
  ones inside their anchor cell after any `office:annotation` and before the
  `text:p`, materialising an otherwise-absent cell and splitting a repeat run
  around it. Imported drawings are their patched `sourceXml`; new ones get
  generated graphic styles `de-gr{n}`.
- **Canonical new drawings** (golden-first; uncertain details are settled in
  the goldens, never guessed in code): an image is
  `<xdr:twoCellAnchor editAs="oneCell">` + from/to + `xdr:pic` (`xdr:nvPicPr`
  with `cNvPr id name descr?`, `a:picLocks noChangeAspect="1"`;
  `xdr:blipFill` with `a:blip r:embed` and `a:stretch/a:fillRect`; `xdr:spPr`
  with `a:xfrm` and `a:prstGeom prst="rect"`) + `<xdr:clientData/>`; a shape
  is `<xdr:twoCellAnchor>` + `xdr:sp macro="" textlink=""` with `xdr:spPr`
  (`a:xfrm`, `a:prstGeom` from `GEOMETRY_TO_PRST` + `a:avLst`, `a:solidFill`,
  `a:ln w`) and an empty `xdr:txBody`. Names are "Picture {k}" and
  "{definition label} {k}", `k` = the minted `cNvPr` id − 1 (Excel's own
  numbering). ODS: `draw:frame` > `draw:image` (`xlink:type="simple"
  xlink:show="embed" xlink:actuate="onLoad"`) and `draw:custom-shape` >
  `draw:enhanced-geometry draw:type` from `GEOMETRY_TO_DRAW_TYPE`, each with
  `draw:z-index`, `draw:name`, `draw:style-name`, `svg:*` geometry in cm and
  `table:end-cell-address` for `moveAndSize`.

### Media parts
`mediaId` is the package path: `xl/media/image{n}.{ext}` / `Pictures/image{n}.{ext}`,
`n` = 1 + the highest numeric suffix across `opaque` and `media`. The writers
treat `model.media` as the source of truth for these paths — a part in
`media` is emitted from there, taking precedence over an `opaque` twin.
xlsx: a missing `<Default Extension="png" ContentType="image/png"/>` (etc.)
is spliced into `[Content_Types].xml` once per extension and the drawing
`.rels` gains an `…/relationships/image` relationship (`rId` = 1 + highest);
ods: `META-INF/manifest.xml` gains the file entry. Readers defer base64 with
`registerPendingMedia`, as the slide reader does.

### Paste
On paste into the grid, a clipboard item of an accepted image type is
inserted as an image at the active cell when the `text/html` flavour (if any)
holds no `<table>` and no SPEC-125 internal payload; otherwise SPEC-125's
cell paste runs. A screenshot therefore inserts; a range copied from Excel
(which also carries a PNG) pastes cells.

### The drawing layer
`src/components/spreadsheet/SheetDrawingLayer.vue` (one per grid pane),
`SheetDrawingView.vue` (one drawing: a canvas, an `<img>` or a placeholder)
and `SheetDrawingHandles.vue`; `src/views/spreadsheet/useSheetDrawings.ts`
(selection, keyboard, commands) and `useDrawingGestures.ts` (insert/move/
resize gestures), each under `composableSize.spec.ts`'s 400 lines.
`SpreadsheetView.vue` gains only their wiring; its ratchet goes down or
stays. Only drawings whose rectangle intersects the pane's visible window
plus one screen of overscan are mounted. Placeholders are a dashed 1.5 px
`#888888` rectangle with the label centred, the look `paintChart` uses for an
unsupported chart. `ShapeGallery.vue` gains a `catalogueOnly` boolean prop
(default `false`, so the document and slide galleries are unchanged) that
hides its Connectors and Freeform groups.
