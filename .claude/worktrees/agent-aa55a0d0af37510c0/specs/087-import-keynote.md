## Why
Half the decks people are handed on a Mac are `.key` files. Keynote's
format is not XML-in-a-zip like the two native formats — it is Apple's
iWork Archive: a ZIP of Snappy-compressed Protocol-Buffers object graphs
— so this is an **import**, not an open: the file converts one-way into
the presentation model (slides, text, images, geometry, notes) and lives
on as a deck that saves to `.pptx`/`.odp` through the SPEC-080/081
writers. There is nothing to round-trip and no `.key` writer; fidelity
is bounded, declared, and reported to the user. The decoding layer is
built from scratch in TypeScript because `package.json` is frozen — and
the format facts below were verified against Apple-shipped iWork files
on 2026-08-24 (Keynote 14.x era), so the factory implements from
evidence, not folklore.

**Prerequisite:** the fixture `e2e/fixtures/mini-deck.key` must be
generated by a human running `scripts/make-keynote-fixture.applescript`
(checked in by this spec's authoring change) on a Mac with Keynote, and
committed, before this spec is labelled `ready`. CI containers cannot
run Keynote; a synthesised `.key` would only test our own assumptions.

## Acceptance criteria
- [ ] `.key` joins the open surface: `OPENABLE_EXTENSIONS` gains `"key"`, the pickers' accept string becomes `.docx,.odt,.md,.markdown,.pptx,.odp,.key`, and the drop error reads "We can only open .docx, .odt, .md, .pptx, .odp and .key files" — with every e2e/unit assertion of the old strings updated in the same change (they live in the SPEC-004/005/009/050 suites and `AppShell.spec.ts`; a repo-wide regex sweep is the required method, per the Download→Export lesson)
- [ ] Detection is content-based inside the ZIP funnel: a ZIP containing `Index/Document.iwa` — or an `Index.zip` whose entries include `Document.iwa` (both layouts exist in the wild; handle both) — takes the Keynote path regardless of extension; `presentationFormatOf` and the docx/odf paths are unaffected
- [ ] A ZIP with `index.apxl` or `index.apxl.gz` (iWork ’05–’09) is rejected with exactly "This is a Keynote ’09 file — open it in Keynote and save it again, or export it as .pptx, then try that file"
- [ ] An IWA package whose root document archive is not a Keynote presentation (Pages/Numbers `.pages`/`.numbers`, or an undecodable graph) is rejected with "This iWork file isn't a Keynote presentation we can open"; decode failures of a plausible `.key` reject with "This Keynote file can't be opened — export it as .pptx from Keynote and try that file"; none of these paths may throw anything but the typed `KeynoteOpenError`
- [ ] Opening `e2e/fixtures/mini-deck.key` yields a `PresentationModel` with `format: "pptx"`, no `opaque`, every slide implicitly rebuilt on save (no `partName`/`sourceXml`), title from the file name, and the fixture's content contract (Reference table): slide count, title/body text per slide, an `ImageFrame` whose media bytes equal the fixture's embedded PNG, and the speaker note string on slide 2
- [ ] Slide geometry converts correctly: Keynote points scale to the model's cm space by the rule in the Reference (16:9 decks land at 33.867×19.05cm); frame positions/sizes land within 0.05cm of the scaled expectation for the fixture's known geometry
- [ ] Text imports as paragraphs split on `\n` (attachment control characters U+FFFC and Unicode paragraph separators handled per the Reference), with role-based default styling (title/body/other per the Reference table — Keynote's own run formatting is out of scope and documented as such); body placeholders get disc bullets, titles none
- [ ] Speaker notes import into `Slide.notes` (SPEC-083's field); slides without notes have none
- [ ] Images import: each image drawable becomes an `ImageFrame` + `MediaPart` (media id minted per SPEC-082's naming rule), bytes taken verbatim from the package's `Data/` entry resolved through the metadata index; images whose data cannot be resolved are dropped and counted
- [ ] Everything else — shapes, tables, charts, movies, groups, per-run text styling, Keynote transitions and builds — is dropped and counted; after the model is stored, the user sees a non-blocking import notice: "Imported from Keynote. N objects and M effects couldn't be imported." (singular/zero forms handled; nothing shown when both are zero), and the deck opens at `/slides/:id` fully editable
- [ ] The importer is defensive by construction: unknown protobuf fields are skipped by wire type, unknown archive types are ignored, truncated chunks/messages raise the typed error, reference cycles terminate (visited-set), and a 50-slide synthetic stress graph decodes without stack overflow (iterative, not recursive, snappy + graph walks)
- [ ] The decode stack (`snappy.ts`, `protobuf.ts`, `iwa.ts`) is DOM-free and Node-runnable (vitest without jsdom facilities), with direct unit tests over hand-built byte cases: snappy literals/copies across chunk boundaries, varint edge values (0, 300, 2^32, 2^53-ish), each wire type, ArchiveInfo parsing
- [ ] Unit tests read the real fixture from `e2e/fixtures/mini-deck.key` via Node `fs` and assert the full content contract; if the fixture file is absent the suite fails with a clear "run scripts/make-keynote-fixture.applescript on a Mac" message rather than passing vacuously
- [ ] e2e (`e2e/SPEC-087.spec.ts`): drag `mini-deck.key` onto the app → import notice visible → deck opens with slide 1 title on the stage → library lists it with a PPTX badge → download produces a `.pptx` that re-opens with the same content contract
- [ ] `titleFromFileName` strips `.key`; the library and header title is "mini-deck" for the fixture

## Out of scope
Any `.key` writing or retention (the import is a conversion; SPEC-008's
retention rule explicitly does not apply — there is nothing we could
re-emit that Keynote would reopen). Keynote run-level text styling,
paragraph alignment, list nesting levels (flat disc bullets only),
shapes/tables/charts/movies/audio, master/theme import (backgrounds
become white), transitions/builds mapping (dropped and counted; a future
spec may map the common ones onto SPEC-085/086's models), password-
protected `.key` (encrypted IWA → the typed error), `.key` *directory
bundles* (a browser file input cannot deliver them; the drag-drop of a
bundle surfaces the standard unsupported-type error), `.pages`/
`.numbers` import, iCloud links.

### Module layout
`src/lib/presentation/keynote/` (presentation-internal; imports core +
presentation siblings only — the boundary spec extends to it):
- `snappy.ts` — raw-block decoder: `snappyDecode(bytes): Uint8Array`.
- `protobuf.ts` — wire reader: varint/fixed32/fixed64/length-delimited
  cursor + a `fields(message): Iterable<{num, wire, bytes|value}>`
  helper; no schema compiler, no codegen.
- `iwa.ts` — chunk framing + archive stream:
  `decodeIwa(bytes): Uint8Array` and
  `parseArchives(stream): Map<bigint, { type: number, payload: Uint8Array }[]>`.
- `reader.ts` — `parseKeynote(bytes, title): Promise<{ model-parts,
  dropped: { objects: number, effects: number } }>` returning what
  `openDocument.ts` assembles; `KeynoteOpenError`; `isIwaPackage(parts)`
  / `isLegacyKeynote(parts)` predicates for the funnel.

### Verified format facts (2026-08-24, Apple-shipped iWork data)
1. Container: plain ZIP; `Index/*.iwa` object files, `Data/*` media,
   `Metadata/Properties.plist`, `Metadata/DocumentIdentifier`. Entries
   commonly STOREd. (Variant: older files nest `Index.zip` holding the
   `.iwa`s — unzip it with the same `core/zip.ts`.)
2. IWA file = a sequence of chunks: 1 header byte `0x00`, then a 3-byte
   little-endian payload length, then the payload. No other chunk types,
   no checksums.
3. Chunk payload = **raw Snappy block**: a varint uncompressed length,
   then literal/copy tags (2-bit tag low bits: 0 literal, 1 near copy
   with 3-bit length + 11-bit offset, 2 copy with 16-bit LE offset, 3
   copy with 32-bit LE offset). No framing-format stream identifier, no
   CRC. Chunks concatenate into one object stream.
4. Object stream = repeated `[varint length][TSP.ArchiveInfo][payload
   messages]`. `ArchiveInfo`: field 1 = object identifier (varint),
   field 2 = repeated `MessageInfo`; `MessageInfo`: field 1 = type
   (varint), field 3 = payload length in bytes (consume that many after
   the info block; multiple MessageInfos mean consecutive payloads).
5. Cross-object references are sub-messages `{ field 1: varint
   identifier }` (TSP.Reference). Data references use the same shape;
   data ids resolve through the metadata index (fact 7).
6. Verified archive types: **1** = KN.DocumentArchive — field 2 → the
   show. **2** = KN.ShowArchive — field 3 = slide-tree message whose
   field 2 is the **repeated, ordered list of top-level slide nodes** —
   one per slide, each referencing its slide at node field 2 (corrected
   2026-09-02 against the real fixture: there is no single "root" node;
   a node's fields 10/16/29 are a size, an id and an undecodable blob,
   not child nodes); field 4 = size `{1: float32 width,
   2: float32 height}` in Keynote points (1920×1080 for 16:9). **4** =
   KN.SlideNodeArchive — field 2 → its KN.SlideArchive (field 16 holds
   a thumbnail data ref — ignore). **5** = KN.SlideArchive — field 5 →
   title placeholder, field 6 → body placeholder, field 7 = repeated
   drawable refs (z-order), field 17 → base/template slide, field 27 →
   notes-related ref (confirm against the fixture), field 4 = transition
   info (ignore). **7** = KN.PlaceholderArchive — field 1 is a
   ShapeInfo-style super whose field 1 chains to the drawable geometry:
   `{1: {1: TSD.GeometryArchive}}` where GeometryArchive = `{1: position
   {1: float32 x, 2: float32 y}, 2: size {1: float32 w, 2: float32 h}}`;
   the super's field 2 → the text storage. **2001** =
   TSWP.StorageArchive — field 2 → stylesheet (ignore), field 3 =
   repeated string: the text (absent in Apple's templates, present in
   documents). Paragraphs within a storage string are separated by
   **U+000D** (carriage return; corrected 2026-09-02 against the real
   fixture) — split on `\r\n`, `\r`, `\n` and U+2029. **11006** = TSP.PackageMetadata, always object id 2 in
   `Index/Metadata.iwa` — field 3 = repeated component `{1: root object
   id, 2: name, 3: iwa file base name}`, field 4 = repeated data `{1:
   data id, 2: 20-byte SHA-1, 3: preferred file name}`.
7. On-disk media: the `Data/` entry for data id N has a base name ending
   `-N` (e.g. `…-353.jpg`); resolve by that suffix, falling back to the
   preferred-file-name match.
8. Slide order (corrected 2026-09-02 against the real fixture): the
   show's slide tree carries the repeated, ordered top-level node list
   itself (fact 6, ShowArchive field 3 → tree field 2) — one node per
   slide. Nested child nodes (skipped slides / grouped decks) still
   hang below each top-level node via its repeated reference field
   whose targets are all type-4 nodes. **Resolution rule (normative):**
   start from the tree's own node list, appending each node's nested
   type-4 children after it; fall back to (b) the type-4 archives in
   the order their components appear in `PackageMetadata` field 3 —
   excluding all top-level nodes already ordered — only for graphs
   where the tree list yields nothing.

### Import mapping (normative)
- **Scale**: target width 33.867cm when the show's aspect is within 2%
  of 16:9,
  25.4cm within 2% of 4:3, else 33.867cm; `slideHeightCm` =
  height × (targetWidth / width). Every point coordinate maps
  `cm = pt × (targetWidthCm / showWidthPt)`.
- **Drawables** (slide field 7, in order): a drawable that resolves to a
  placeholder/shape with a text storage → `TextFrame`; role: the slide's
  field-5 target is "title", field-6 target is "body", anything else
  "other". A drawable whose message graph (searched breadth-first
  through sub-messages, depth ≤ 6) contains a data reference resolving
  to a `Data/` entry with an image extension (png/jpg/jpeg/gif/tiff/
  heic — tiff/heic are dropped-and-counted since browsers can't decode
  them portably) → `ImageFrame`. Anything else → dropped, counted.
  Geometry: the first GeometryArchive-shaped submessage on the
  drawable's super chain; a drawable with no resolvable geometry gets
  the role's default band (title: x 8% y 8% w 84% h 16%; body: x 8%
  y 30% w 84% h 60%; other/image: centred at 50% width, 4:3 box).
- **Text**: storage field 3 strings concatenated; split into paragraphs
  on `\n` and U+2029; drop U+FFFC (object replacement) and zero-width
  characters; skip empty storages. Styling defaults: title → 36pt bold
  #000000, subtitle-like "other" on slide 1 → 20pt, body → 18pt with
  `bullet: "disc"`; font family left unset (renderer default stack).
- **Notes**: resolve slide field 27; if it (or its placeholder chain)
  reaches a storage, its paragraphs → `Slide.notes`. Confirmed against
  the fixture; absent field → no notes.
- **Properties**: only `title` (from file name). `Metadata/
  Properties.plist` is a binary plist — not parsed (no dependency
  budget for bplist; documented).
- **Assembly**: slides with zero imported frames still import (blank
  slide, keeps count parity with Keynote); a deck resolving to zero
  slides → the typed error, not an empty deck.

### Funnel integration
In `openFile` (`openDocument.ts`), after `detectPackage` and the
presentation dispatch, before the odf/docx fallthroughs:
`isIwaPackage(parts)` → (text-only entry points reject with
`PRESENTATION_NOT_TEXT_MESSAGE` exactly like native presentations) →
`parseKeynote` → `{ kind: "presentation", model }` with the import
notice payload threaded to the caller the same way SPEC-050 threads its
conversion report (an optional field on the opened result, surfaced by
the open paths that show UI). `isLegacyKeynote` → the ’09 error.
`.key` never reaches the docx path.

### The fixture and its generator
`scripts/make-keynote-fixture.applescript` (checked in): builds a
two-slide 1920×1080 deck — slide 1 title "Keynote fixture deck" +
subtitle/body "Imported by docu-edit"; slide 2 title "Second slide",
body "First bullet point"⏎"Second bullet point", an embedded 8×8 PNG
image (the script writes it beside the output), presenter note "A
speaker note for the importer" — and saves
`e2e/fixtures/mini-deck.key`. Content contract (what tests assert):

| fact | value |
| --- | --- |
| slides | 2 |
| slide 1 | title frame "Keynote fixture deck"; a text frame containing "Imported by docu-edit" |
| slide 2 | title "Second slide"; body paragraphs ["First bullet point", "Second bullet point"] with disc bullets; one ImageFrame (PNG, 8×8, bytes equal to the checked-in `e2e/fixtures/fixture-image.png`); notes ["A speaker note for the importer"] |
| model | format "pptx", no opaque, title "mini-deck" |

If Keynote's master naming makes the exact frame roles differ (the
script falls back when a named master is missing), the person
generating the fixture re-runs until the report the script prints shows
all steps `ok`, so the contract holds.
