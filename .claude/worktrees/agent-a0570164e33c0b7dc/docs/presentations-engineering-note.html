One repo, two document products

docu-edit now carries a second product beside the word processor: presentations. A .pptx or .odp opens from every open path, lives in the same library, previews read-only at /slides/:id, and downloads back with every source part byte-identical. This note is the architecture that makes the two products share an engine without ever touching each other.

The layering

Three layers, one rule: the products meet only in the app layer, and everything both need is product-neutral by definition and lives in core. The dashed struck edge is the load-bearing decision — it is a test, not a convention.

What shipped in this preparation

  • newA working presentations slice. Content-based detection (never extensions) recognises PresentationML and ODF-presentation packages; readers extract a per-slide text outline (titles from placeholders, grouped shapes included) and retain every package part verbatim; writers re-emit the package — the SPEC-008 promise applied wholesale, with .odp's mimetype first and STOREd.
  • new/slides/:id. A deliberately read-only PresentationView: title, format, slide outline, byte-preserving Download, honest "editing isn't supported yet" note. Router guards redirect each kind's ids to its own view, so neither product can load the other's model.
  • sharedThe library is now kind-aware. One store holds both models (StoredModel union discriminated by kind); rows carry PPTX/ODP badges and filter chips; grid cards show "3 slides" instead of pages·words; bulk download dispatches per kind; text-only accessors (getDocument, drafts, autosave) are hard-narrowed so a deck can never be clobbered by editor state.
  • sharedThe landing page is its own module. HomeView (1,476 → 651 lines) is a wiring hub over six product-neutral src/views/library/ components; product knowledge (what can be created, where kinds route) stays in the hub. HomeView.size.spec.ts ratchets it, DocumentView-style.

Word-processor code that became shared

Everything a presentation package needs that the word processor already had — none of it was word-shaped, all of it moved to core (text-side imports kept working via re-exports where the surface was wide):

How the refactor ran

Neutral moves into core

Metadata types, docProps/meta parsers, ODF namespaces, opaque-part machinery, package detection — moved with re-export shims where import surfaces were wide, direct rewires where they were narrow. Green after: typecheck + boundary + round-trip suites.

Kind registry + store union

documentKinds.ts becomes the single encoding of "pptx means presentations at /slides". The store's record model widens to a discriminated union; accessors narrow by kind; LibraryEntry carries kind. Format chips, badges and counts widen compile-checked.

The presentation layer

lib/presentation/: minimal model, pptx/odp readers (outline + full retention), verbatim writers, funnel, download — plus its own boundary spec and a round-trip suite proving part-level byte identity both ways.

App integration

openAnyDocumentFile union funnel (single-unzip detection; text-only entry points keep their contract and reject decks honestly), /slides/:id + router kind-guards (kept out of DocumentView, which sat one line under its ratchet), AppShell drop, URL-open, HomeView, kind-aware cards and downloads.

Landing page module

Six product-neutral components extracted from HomeView into src/views/library/ with every test-id and ARIA role preserved; shared logic into useLibrary and lib/libraryMenu; a new size ratchet holds the floor.

Fixtures + end-to-end proof

One DOM-free builder generates both the unit fixtures and the checked-in e2e/fixtures/mini-deck.pptx|odp; e2e/presentations.spec.ts walks open → badge → preview → kind-redirect → download and byte-compares every part against the source.
